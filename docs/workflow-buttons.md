# Этапы и кнопки маршрутов

В разделе «Администрирование → Кнопки этапов» создаются и редактируются надписи, оформление и действия кнопок. Кнопку можно отключить для новых версий маршрутов. Для возврата и отклонения комментарий всегда обязателен; для остальных действий это настраивается.

Действия:

- `complete`: завершить задачу исполнителя. Следующий этап начинается, когда выполнено правило `all` или `any`.
- `start`: принять задачу в работу без перехода дальше. Кнопка исчезает после нажатия, задача остаётся в списке и журнале «На исполнении».
- `return`: завершить текущий маршрут и вернуть документ автору на доработку. После правки автор может запустить маршрут заново.
- `reject`: отклонить документ и завершить текущий маршрут.

В конструкторе доступны согласование, исполнение, ознакомление и регистрация. Тип этапа предлагает начальный набор кнопок, который можно изменить. Каждому этапу задаются инструкция, исполнители, правило завершения и условие выполнения. Условие поддерживает явно выбранный тип значения: текст, число или логическое значение. Итоговый статус документа выбирается отдельно: «Исполнен» или «Согласован».

Код нового маршрута можно оставить пустым — он создаётся автоматически. При сохранении форма показывает подтверждение и остаётся на сохранённой версии. Редактирование создаёт новую версию; попытка сохранить устаревшую версию возвращает конфликт.

Сервер при сохранении берёт настройки выбранных кнопок из справочника и сохраняет их вместе с версией маршрута. Изменение справочника применяется к маршруту при следующем сохранении его новой версии. Запущенные экземпляры используют собственный снимок, включая кнопки и их поведение. Старые экземпляры без настроек кнопок сохраняют действия «Согласовать», «Вернуть», «Отклонить».

API:

- `GET /api/v1/admin/buttons` — справочник (только администратор).
- `POST /api/v1/admin/buttons`, `PUT /api/v1/admin/buttons/{code}` — создание и изменение.
- `POST /api/v1/tasks/{id}/decision` принимает `action_code` и `comment`. Сервер проверяет исполнителя, состояние задачи, доступность кнопки в снимке этапа и обязательный комментарий. Старый параметр `decision` сохранён для совместимости, но также проверяется по доступным кнопкам.

Миграция `0002_workflow_buttons.sql` добавляет справочник, статусы исполнения и сведения о нажатой кнопке. Все изменения выполняются транзакционно. Одновременные решения по задачам одного экземпляра сериализуются блокировкой экземпляра маршрута.

## Проверка

`go test ./...` запускает обычные тесты. Для интеграционных сценариев задайте `DOCFLOW_TEST_DATABASE_URL` на отдельную пустую PostgreSQL-базу с именем, начинающимся с `docflow_test_`. Тест создаёт схему и данные; повторный запуск требует новой пустой базы.

Интеграционные сценарии проверяют сохранение и версии маршрутов, снимки кнопок, права исполнителей, обязательный комментарий, принятие в работу, журналы, завершение всеми/любым исполнителем, возврат и повторный запуск, отклонение, пропуск по условию, параллельные решения и совместимость со старыми маршрутами.
