# DocJet

Корпоративный электронный документооборот. Монорепозиторий с API на Go, PostgreSQL и веб-интерфейсом React/TypeScript. Первый релиз ориентирован на работу внутри организации.

## Запуск

Понадобятся Docker Engine и Docker Compose v2.

```bash
cp .env.example .env
```

Измените в `.env` значения `POSTGRES_PASSWORD`, `APP_SECRET`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`. Для `APP_SECRET` рекомендуется использовать случайную строку:

```bash
openssl rand -hex 32
```

Старт:

```bash
docker compose up --build -d
docker compose ps
```

Веб-интерфейс: **http://localhost:8081**. Административная учётная запись создаётся при **первом** запуске из `ADMIN_EMAIL` и `ADMIN_PASSWORD`. Пароль не хранится в открытом виде в базе данных. После изменения переменной пароля существующий пользователь автоматически не обновляется.

Проверка состояния API через контейнер web:

```bash
docker compose exec web wget -qO- http://api:8080/api/v1/health
```

Ожидаемый ответ: `{"status":"ok"}`.

Для локальной разработки отдельно (нужны Go 1.23+, Node 22+, PostgreSQL 16+):

```bash
cd backend
go mod tidy
go run .

# в другом терминале
cd frontend
npm install
npm run dev
```

Локальный backend использует `DATABASE_URL`, `APP_SECRET`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `STORAGE_DIR`. Vite проксирует `/api` на порт `8080`.

## Возможности первого релиза

| Модуль | Реализация |
|---|---|
| Документы | Создание, отдельная страница с карточкой, PDF-предпросмотром и ходом исполнения, журналы и поиск, мягкое удаление, восстановление |
| Типы документов | Стандартные типы плюс типы из админки; настраиваемые поля, включая выбор пользователя, и маршрут по умолчанию |
| Исполнение | Последовательные и параллельные этапы `all`/`any`, условные переходы, согласование, ознакомление, возврат, отклонение |
| Конструктор | Версии схем, назначение по группе или полю документа, инструкции, кнопки, условия и параллельные блоки |
| Права доступа | Локальные пользователи с ролями `admin`, `registrar`, `employee`; отделы и должности |
| Файлы | Загрузка PDF/DOCX до 20 МБ, история версий, предпросмотр PDF |
| DOCX шаблоны | Подстановка полей документа в DOCX, генерация новой версии вложения |
| Интеграции | REST API, интеграционные токены, webhook через транзакционный outbox |
| Аудит | События создания, правки, маршрутизации, принятия решений и удаления |
| Локальный ИИ | Тестовый текстовый чат через Ollama и небольшую модель; открывается кнопкой слева снизу |

Роль **admin** может создавать/редактировать типы документов, пользователей, маршруты, шаблоны и webhook-подписки, удалять документы и восстанавливать их из корзины. Регистратор может просматривать все не удалённые документы и запускать маршруты; обычные сотрудники видят собственные документы и документы, назначенные им на исполнение или согласование.

## Организация исходников

```text
backend/
  main.go           запуск, конфигурация, маршрутизация HTTP, миграции
  auth.go           логин, JWT, refresh с ротацией
  admin.go          пользователи, отделы, должности, типы
  documents.go      журналы, карточки, валидация реквизитов, события
  workflow.go       версии маршрутов, создание задач, серверные переходы
  files.go          файловое хранилище, DOCX шаблоны
  integrations.go   webhook, HMAC подписи, выдача сервисных токенов
  migrations/       схема PostgreSQL
frontend/
  src/App.tsx       рабочее место, журналы, карточки, задачи
  src/Admin.tsx     административные разделы и конструктор
  src/model.ts      API клиент и типы
  src/style.css     интерфейс
```

На уровне backend используется транзакционное согласование: при принятии решения блокируется экземпляр маршрута (`SELECT ... FOR UPDATE`), обновляется текущая задача и запускается следующий этап. Один параллельный этап не должен быть активирован повторно из-за одновременных запросов. Запущенный экземпляр хранит неизменяемый JSON-снимок схемы, а обновление конструктора создаёт **новую версию**. Изменение маршрута не затрагивает уже выполняющиеся документы.

## Данные PostgreSQL

Основная таблица `documents` содержит нормализованные колонки: `id`, `type_id`, `registration_number`, `title`, `summary`, `status`, `author_id`, `assignee_id`, `department_id`, `due_at`, `registered_at`, `created_at`, `updated_at`, `deleted_at` и JSONB `fields`. Реестр `document_types.fields` определяет схемы дополнительных реквизитов (`key`, `label`, `type`, `required`, `options`). Backend отвергает неизвестные поля и значения неправильного типа.

Маршруты: `workflow_definitions` — версии схем; `workflow_instances` — фактические запуски; `workflow_tasks` — индивидуальные задания; `document_events` — история. Вложения с версиями хранятся в `files`, а бинарные объекты в подключённом томе `file_data` (к базе не привязаны BLOB). Для замены на S3/MinIO потребуется выделить файловые операции в отдельный интерфейс, сохранив идентификаторы и метаданные.

Подробнее: [docs/architecture.md](docs/architecture.md) и [docs/api.md](docs/api.md).

## Правила маршрутов

Пример `definition`:

```json
{
  "steps": [
    {
      "id": "head_review",
      "title": "Руководитель подразделения",
      "mode": "all",
      "assignee_ids": ["<uuid руководителя>"]
    },
    {
      "id": "legal_check",
      "title": "Юридическая экспертиза",
      "mode": "any",
      "assignee_ids": ["<uuid сотрудника 1>", "<uuid сотрудника 2>"],
      "condition": {"field": "amount", "operator": "gt", "value": 100000}
    }
  ]
}
```

Строки `<uuid ...>` в этом примере нужно заменить настоящими идентификаторами пользователей из API. `mode=all` — нужны решения всех; `mode=any` — достаточно одного подтверждения, оставшиеся задания отменяются. Условия поддерживают `eq`, `neq`, `gt`, `gte`, `lt`, `lte`, `contains`. При ложном условии этап пропускается. `return` завершает текущий экземпляр со статусом «На доработке»: автор может исправить документ и запустить маршрут повторно. `reject` завершает экземпляр со статусом «Отклонён».

## Шаблоны DOCX

Поддерживаются подстановки `{{title}}`, `{{registration_number}}`, `{{summary}}`, `{{created_at}}` и `{{код_поля}}` внутри XML-файлов документа Word. Плейсхолдер должен быть набран одним текстовым фрагментом; при разбиении Word на несколько `w:t` автоматическое объединение в этой версии не выполняется. Генерация PDF из DOCX и серверный предпросмотр DOCX не входят в текущий релиз: предпросмотр работает для готовых PDF.

## Важные ограничения и планы


Требуют отдельной реализации: НУЦ РК/ЭЦП, подписание PDF, рассылка уведомлений, файловый антивирус, полноценный DOCX-рендеринг, полнотекстовый поиск по содержимому вложений, графический drag-and-drop редактор маршрутов, массовые операции, удаление данных без возможности восстановления, динамические правила назначения согласующих по должности или роли. Настройка новых маршрутов описана в [документации](docs/dynamic-routing.md).

Интеграционные события доставляются **как минимум один раз**. Приёмник должен дедуплицировать по `id`. Webhook разрешены только на внешние публичные HTTPS-адреса; запросы к приватным адресам блокируются. Интеграционные токены обладают доступом к API документов и типов документов от имени создавшего их администратора; храните их как секреты и удаляйте/отзывайте при компрометации (управление отзывом токенов через интерфейс пока не реализовано).
