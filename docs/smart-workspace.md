# Рабочее пространство документов

В DocJet v0.5 добавлены 15 возможностей для повседневной работы с документами.

| № | Возможность | Где использовать |
|---|---|---|
| 1 | Личное избранное | Звёздочка в реестре, кнопка «Избранное», рабочая вкладка документа |
| 2 | Сохранённые представления | «Фильтры» → задать условия → название → «Сохранить вид»; наборы доступны только владельцу |
| 3 | Расширенный поиск | Совместные фильтры по статусу, типу, автору, ответственному, подразделению, датам создания, сроку, приоритету и метке; сортировка и страницы |
| 4 | Метки | «Обсуждение и контроль» → метки через запятую; нажатие метки в реестре включает фильтр |
| 5 | Приоритеты | Низкий, обычный, высокий, срочный; фильтр и сортировка по приоритету |
| 6 | Обсуждения | Комментарии в рабочей вкладке документа, с автором и временем |
| 7 | Упоминания | Выбор сотрудников через поиск и оргструктуру, уведомление с переходом в обсуждение, отдельная настройка в профиле |
| 8 | Чек-листы | Добавление и выполнение пунктов, прогресс и имя выполнившего |
| 9 | Связанные документы | Поиск доступного документа и связи «Связанный документ», «Основание», «Ответ на документ»; видны входящие и исходящие связи |
| 10 | Копирование в черновик | Копируются актуальные реквизиты, метки и приоритет; автором становится текущий пользователь; номера, задачи, файлы, подписи и связи не копируются |
| 11 | Массовые действия | Выделить до 50 документов: добавить в избранное, изменить приоритет, добавить метку; результат по каждому документу |
| 12 | CSV-экспорт реестра | «CSV ↓» выгружает документы по текущим фильтрам, с UTF-8 BOM и разделителем `;`; значения, похожие на формулы, экранируются |
| 13 | Календарь сроков | Вкладка «Календарь» в реестре, выбор месяца и дня, переход к документу |
| 14 | Аналитика | Вкладка «Аналитика»: количество документов, просрочки, распределение по состояниям и приоритетам, собственные открытые и просроченные задачи; учитываются текущие фильтры |
| 15 | Версии карточки | Автоматические снимки реквизитов и сравнение двух версий с автором и временем; стандартные и пользовательские поля |

## Права и границы

Все списки, фильтры, экспорт, календарь, аналитика, версии, связи и массовые действия проверяют существующие права DocJet. Администратор и регистратор читают все действующие документы; сотрудник — свои, назначенные ему и документы, в задачах которых он участвовал. Удалённые документы исключены.

Метки, приоритет, чек-лист и исходящие связи изменяют администратор, автор или ответственный. Любой читатель документа может добавить комментарий, создать свою копию и управлять собственным избранным. Упоминать можно только активных сотрудников, уже имеющих доступ к документу. Связи, избранное и упоминания не предоставляют новые права. Настройки уведомлений применяются при создании упоминания; ранее полученные уведомления сохраняются.

Изменения реквизитов, обсуждения, чек-листы и связи попадают в аудит. Сохранение метаданных требует `expected_updated_at` и возвращает 409 при конфликте. Снимки карточки создаёт триггер PostgreSQL, в том числе для изменений из других существующих API. Изменения до установки функции не восстанавливаются: миграция сохраняет текущее состояние каждого документа как v1. Версии файлов остаются отдельным существующим механизмом. Сравнение карточек не восстанавливает старую версию и не изменяет документ.

Ограничения: 20 личных представлений; 20 меток по 40 символов; 4000 символов и 20 упоминаний в комментарии; показываются последние 100 комментариев; 200 пунктов чек-листа; до 100 видимых связей и 100 последних версий в интерфейсе. CSV содержит до 5000 документов, календарь — до 500 за месяц с явным предупреждением о превышении. Календарь и фильтры дат используют Asia/Qyzylorda (UTC+5). Чек-листы помогают подготовке и не заменяют задачи маршрута.

## API

Все маршруты требуют обычную авторизацию DocJet и префикс `/api/v1`.

| Метод и путь | Назначение |
|---|---|
| `GET /documents` | Существующий список, расширен фильтрами `q`, `journal`, `status`, `type_id`, `author_id`, `assignee_id`, `department_id`, `favorite`, `priority`, `tag`, `created_from/to`, `due_from/to`, `due`, `sort`, `limit`, `offset` |
| `GET /documents/export` | CSV по тем же фильтрам |
| `GET /workspace/analytics` | Агрегаты по фильтрам и правам |
| `GET /workspace/calendar?month=YYYY-MM` | Сроки доступных документов |
| `GET, POST /workspace/views` | Личные представления; POST принимает `name`, `filters` |
| `DELETE /workspace/views/{id}` | Удалить собственное представление |
| `POST /workspace/bulk` | `ids`, `action` (`favorite`, `priority`, `tag_add`), соответствующее значение; отдельный результат для каждого id |
| `GET /documents/{id}/workspace` | Метаданные, избранное, обсуждение, чек-лист, доступные связи, право редактирования |
| `PUT /documents/{id}/favorite` | `favorite: boolean` |
| `PATCH /documents/{id}/metadata` | `priority`, `tags`, обязательный `expected_updated_at` |
| `POST /documents/{id}/comments` | `body`, `mentions: uuid[]` |
| `POST /documents/{id}/checklist` | `label` |
| `PATCH /documents/{id}/checklist/{item}` | `done: boolean` |
| `DELETE /documents/{id}/checklist/{item}` | Удалить пункт |
| `POST /documents/{id}/links` | `target_id`, `kind` (`related`, `basis`, `response_to`) |
| `DELETE /documents/{id}/links/{item}` | Удалить исходящую связь |
| `POST /documents/{id}/duplicate` | Новый черновик, необязательное `title`; возвращает новый id |
| `GET /documents/{id}/versions` | Метаданные последних 100 версий |
| `GET /documents/{id}/versions/compare?from=N&to=M` | Отличающиеся значения реквизитов |

В `GET/PUT /me/notification-preferences` добавлен флаг `mentions`, по умолчанию включён. Существующий MCP использует прежний REST API; новые специализированные команды рабочего пространства в MCP этим изменением не добавляются.

## Исследование

Реализация адаптирует общие продуктовые идеи из официальных материалов поставщиков, без копирования их интерфейса или кода:

- [Directum: управление документами](https://www.directum.ru/solution/rx_document_management) — работа с жизненным циклом и связанными документами.
- [Directum: контроль исполнительской дисциплины](https://www.directum.ru/solution/rx_discipline_control) — мониторинг сроков, показатели и аналитика.
- [M-Files: связи объектов](https://userguide.m-files.com/user-guide/latest/eng/object_relationships.html) — ссылки между объектами.
- [M-Files: представления](https://userguide.m-files.com/user-guide/latest/eng/creating_views.html?hl=create%2Cview) — сохранение подборок документов.
- [SharePoint: фильтрация представления](https://support.microsoft.com/en-us/sharepoint/data-and-lists/use-filtering-to-modify-a-sharepoint-view) — сочетание условий отбора.
- [SharePoint: управление версиями](https://learn.microsoft.com/en-us/sharepoint/version-overview) — история и отслеживание изменений.

Набор из 15 функций — выбор для текущего DocJet; это не утверждение, что каждая перечисленная система реализует каждую функцию в таком же виде.

## Проверка

`backend/workspace_test.go` проверяет фильтры, защиту CSV, нормализацию меток и полный цикл новых API на отдельной базе с именем `docflow_test_*`. Интеграционные тесты включаются через `DOCFLOW_TEST_DATABASE_URL`; без неё тест пропускается. Проверяются личные данные, отсутствие утечек по связям/экспорту/аналитике, упоминания с настройками, конфликт сохранения, чек-листы, чистая копия, частичные результаты массовых действий, границы месяца UTC+5 и снимки версий. Существующие проверки маршрутов, журналов и уведомлений запускаются в той же проверке.
