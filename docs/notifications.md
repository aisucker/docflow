# Уведомления DocJet v0.5

Колокольчик в верхней панели открывает личный центр уведомлений. Он показывает непрочитанные события, позволяет перейти к документу, отметить одно уведомление или все показанные к моменту загрузки как прочитанные, отфильтровать непрочитанные и загрузить более ранние записи.

В **Личном кабинете → Уведомления и напоминания** каждый сотрудник независимо включает:

- новые задачи;
- полученные поручения;
- решения по задачам своего документа;
- возврат документа на доработку;
- отклонение документа;
- согласование или исполнение документа;
- приближение срока;
- просрочку.

Общий переключатель отключает создание всех новых уведомлений этого пользователя. Ранее полученная история остаётся доступной. Эти настройки сохраняются отдельно от стартовой страницы и компактного вида таблиц. Напоминание можно установить за 1–168 часов до срока документа, по умолчанию за 24 часа.

Уведомления о задачах создаются в одной транзакции с выдачей задачи и событиями маршрута. Решения получают автор и ответственный документа; одинаковые получатели не дублируются, а сотрудник не получает уведомление о собственном решении. Получатель поручения уведомляется отдельно. Финальный результат маршрута может уведомить и его инициатора.

Сервер проверяет открытые задачи раз в минуту и сразу после запуска. На каждую задачу и конкретный срок создаётся максимум одно предварительное напоминание и одно сообщение о просрочке. Перезапуск и одновременная работа нескольких экземпляров API не дублируют их. При переносе срока возможно новое напоминание. Напоминания по завершённым задачам и старым срокам скрываются. Новых уведомлений о событиях, произошедших до установки этой версии, не создаётся; актуальные просрочки существующих задач обнаруживаются при первой проверке.

Доставка реализована **внутри системы**. Колокольчик обновляется каждые 30 секунд, при возвращении к вкладке и после действий в интерфейсе. Для генерации напоминаний API должен работать; при следующем запуске он проверяет актуальные сроки. Email, SMS и браузерные push-уведомления не настроены.

## API

Все операции требуют обычную пользовательскую авторизацию. Пользователь получает только свои уведомления и только по доступным ему неудалённым документам.

| Метод | Ресурс | Назначение |
|---|---|---|
| GET | `/api/v1/me/notification-preferences` | Личные настройки с применёнными значениями по умолчанию |
| PUT | `/api/v1/me/notification-preferences` | Полные или частичные настройки; неизвестные поля и null отклоняются |
| GET | `/api/v1/notifications` | `limit=1..100`, `before_id`, `unread_only=true` |
| POST | `/api/v1/notifications/{id}/read` | Идемпотентно отметить своё уведомление прочитанным |
| POST | `/api/v1/notifications/read-all` | `{ "through_id": <max_id из списка> }`; более новые уведомления остаются непрочитанными |

Список возвращает `items`, `unread_count`, `max_id`, `next_cursor`. Настройки: `enabled`, `task_assigned`, `task_delegated`, `task_completed`, `document_returned`, `document_rejected`, `document_completed`, `due_soon`, `overdue` — boolean; `reminder_hours` — целое число от 1 до 168.

Миграция `0010_notifications.sql` добавляет личные настройки и таблицу уведомлений. Локальные пароли, база, вложения и переписка не входят в Git.
