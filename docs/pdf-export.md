# PDF с QR-проверкой

В карточке документа рядом с вложением есть кнопка «PDF с QR». Она выгружает отдельную PDF-копию подписанной версии, сохраняя исходный файл. В блоке электронных подписей можно выгрузить карточку без вложений. Карточка содержит последний подписанный снимок содержания; регистрационные реквизиты приведены на момент выгрузки.

PDF содержит исходные страницы с отдельными полями для отметок, QR, сведения о подписантах, способе подписи, времени приёма/проверки ЭЦП, проектном и регистрационном номерах. Время приёма не выдается за доверенную метку времени подписания. При нескольких подписях сведения о каждой находятся на дополнительных страницах. ЭЦП — отделённая CMS пакета документа с SHA-256 исходных файлов, не встроенная PAdES-подпись новой PDF-копии.

API (авторизация пользователя и проверка доступа к документу обязательны):

- `GET /api/v1/files/{id}/signed-pdf` — PDF или DOCX, только если сохранённая проверенная подпись покрывает точный ID и SHA-256 файла.
- `GET /api/v1/documents/{id}/signed-pdf` — последняя подписанная карточка документа.

Проверка без входа по непредсказуемой ссылке `/verify/{token}` показывает реквизиты выгрузки, подписантов и контрольные суммы, без содержания документа, ИИН и самих файлов. Любой получатель ссылки может увидеть эти сведения. Токен хранится в БД только как SHA-256. Удалённые документы недоступны. `GET /api/v1/public/verify/{token}` возвращает эти данные; `POST /api/v1/public/verify/{token}/recheck` повторно проверяет сохранённую CMS через настроенный NCANode с проверками доверия и отзыва. Лимит — раз в минуту для выгрузки и две проверки одновременно. Отсутствие подтверждения не показывается как успешная проверка. Выбранный на странице PDF проверяется по SHA-256 в браузере без отправки на сервер.

`PUBLIC_VERIFY_BASE_URL` задаёт базовый URL приложения со страницей проверки. В рабочем окружении нужен доступный получателям HTTPS-адрес. По умолчанию используется `APP_ORIGIN`. `localhost` подходит только для этого ноутбука; телефон и другие компьютеры такую ссылку открыть не смогут. Внешний сервис или туннель автоматически не публикуется.

PDF-сервис: Python 3 с `pip install -r backend/pdf/requirements.txt`; `DOCJET_PDF_PYTHON` — путь к Python, `DOCJET_PDF_FONT` — путь к TTF с кириллицей. DOCX преобразуется установленным Microsoft Word на Windows (отдельный невидимый экземпляр, только чтение, макросы отключены) или LibreOffice на Linux (`DOCJET_SOFFICE`, по умолчанию `soffice`). Docker-образ включает зависимости PDF и LibreOffice. Docker-сборка требует доступа к PyPI и репозиториям Debian.

Шифрованные PDF и документы свыше 200 страниц не поддерживаются. Исходник масштабируется с сохранением пропорций до A4 (альбомного при необходимости), чтобы отметки не перекрывали содержание. Для высокоточной печати остаётся скачивание оригинала.
